# Fuseaux horaires

DayFlow fournit une énumération `TimeZone` pour configurer aussi bien le `timeZone` de l'application que le `secondaryTimeZone` (réservé aux vues Jour et Semaine) sans avoir à mémoriser les chaînes IANA brutes.

## Modèle de fuseaux

- `timeZone` : le fuseau horaire principal d'affichage et d'édition pour tout le calendrier ;
- `secondaryTimeZone` : un axe temporel de référence supplémentaire, affiché uniquement dans les vues Jour et Semaine.

Changer `timeZone` reprojette toutes les vues. Changer `secondaryTimeZone` ne modifie que cet axe supplémentaire dans les vues Jour et Semaine.

## Sémantique des callbacks

- `timeZone` modifie la façon dont les événements sont affichés et modifiés dans l'interface.
- Changer de `timeZone` ne déclenche jamais à lui seul `onEventUpdate`, `onEventDrop` ou `onEventResize`.
- Les callbacks de mise à jour renvoient l'événement canonique une fois la modification appliquée.
- Autrement dit : si un événement de Sydney est consulté depuis Shanghai et redimensionné là-bas, la modification est interprétée à l'heure locale de Shanghai, mais la charge utile du callback est reconvertie vers la représentation temporelle canonique de l'événement avant que vous ne l'enregistriez.

## Utilisation

```tsx
import { TimeZone } from '@dayflow/core';
import {
  useCalendarApp,
  createDayView,
  createWeekView,
  createMonthView,
} from '@dayflow/react';

const calendar = useCalendarApp({
  timeZone: TimeZone.SHANGHAI,
  views: [
    createDayView({
      secondaryTimeZone: TimeZone.NEW_YORK,
    }),
    createWeekView({
      secondaryTimeZone: TimeZone.NEW_YORK,
    }),
    createMonthView(),
  ],
});
```
