# Zonas horarias

DayFlow ofrece un enum `TimeZone` para que configures tanto el `timeZone` de la aplicación como el `secondaryTimeZone` (solo en las vistas de día y semana) sin tener que memorizar cadenas IANA.

## Modelo de zonas horarias

- `timeZone`: la zona horaria principal de visualización y edición de todo el calendario
- `secondaryTimeZone`: una línea temporal de referencia adicional que solo aparece en las vistas de día y semana

Cambiar `timeZone` reproyecta todas las vistas. Cambiar `secondaryTimeZone` solo afecta al eje temporal adicional de las vistas de día y semana.

## Semántica de los callbacks

- `timeZone` cambia cómo se muestran y se editan los eventos en la interfaz.
- Cambiar de `timeZone` nunca dispara por sí solo `onEventUpdate`, `onEventDrop` ni `onEventResize`.
- Los callbacks de actualización devuelven el evento canónico una vez aplicada la edición.
- Dicho de otro modo: si un evento de Sídney se ve desde Shanghái y allí se redimensiona, la edición se interpreta con la hora de reloj de Shanghái, pero la carga útil del callback se convierte de vuelta a la representación temporal canónica del evento antes de que la guardes.

## Uso

```tsx
import { TimeZone } from '@dayflow/core';
import {
  useCalendarApp,
  createDayView,
  createWeekView,
  createMonthView,
} from '@dayflow/react';

const calendar = useCalendarApp({
  timeZone: TimeZone.SHANGHAI,
  views: [
    createDayView({
      secondaryTimeZone: TimeZone.NEW_YORK,
    }),
    createWeekView({
      secondaryTimeZone: TimeZone.NEW_YORK,
    }),
    createMonthView(),
  ],
});
```
